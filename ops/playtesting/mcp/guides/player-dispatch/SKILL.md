# Assign a player to an approved match

Use the account's existing OAuth connection. In Sheoldred, the Discord application verifies Felipe's approval for the specific request before starting a paid pilot or provisioning a slot. Keep the approval, selected table, format, intended deck, slot request UUID and assigned player together when resuming a job.

1. Read the current tool schemas and call `get_guide({"bundle":true})`. For an invitation addressed to your account or player, look up the approved table with `list_joinable_games({"tableId":"<invited-table-uuid>"})`. For an external invitation from a web host, preserve its complete link and call `list_joinable_games({inviteLink})`. Compare its exact `tableId`, format and recipient to the request. A spectator link or a table ID is only a reference. Continue only with a confirmed invitation. If the exact lookup returns no invitation, ask the host to check the recipient.
2. Use `list_players({"availableOnly":true})`. For an exact `guestPlayerId`, select that same player. If it is busy, report the conflict. For an account invitation marked `requiresPlayerAssignment:true`, select a free player owned by that account. An unbound reservation already occupies the slot. For a resumed job check the previously assigned player's reservation before allocating anything else.
3. If an account-addressed invitation has no free player and the approved request allows provisioning, call `create_player_slot({"requestId":"<persisted-request-uuid>","displayName":"Sheoldred 3"})`. Retry with the same UUID and settings. The account owner must have consented to `players:manage` on the canonical connection. A new player also needs the connection's play permission to enter the table. If provisioning is unavailable, report it to the owner.
4. Call `list_decks({"playerId":"<selected-player-uuid>"})` and choose the authorized saved MCP deck for the requested format. Verify the identity of the intended list when names coincide. Join using its returned ID through `join_game({"tableId":"<invited-table-uuid>","playerId":"<selected-player-uuid>","deckId":"<validated-deck-uuid>"})`. For an external invitation, use `join_game({inviteLink,playerId,deckId})` with the same complete link. If a concurrent job took the slot, recheck the invitation and availability. On an uncertain join, call `get_player_reservation({"playerId":"<selected-player-uuid>"})` and reconcile that same table before retrying.
5. Hand the fresh pilot the table, format, deck name and its own player ID. The host starts the match. The pilot reads the live guides and plays through its own seat until the terminal result. The coordinator retains account-wide provisioning and dispatch authority.

In the web lobby, **Rival MCP** invites the host’s own enabled MCP players by default. To invite someone else’s MCP player, the host enables **Allow external players** and privately shares the invitation link from Tables. The first eligible player to accept takes the single rival seat. Directed API invitations still accept `guestAccountName` or `guestPlayerId` on `create_human_match` and `create_game`.
