# Semantic response parity and reevaluation — PM-AC-09-RESPONSES

## Contract
`play_turn` SHALL accept an already observed MCP decision using `choose`, its exact `decisionId`, exactly one `choiceId` or semantic `select`, and the same optional numeric/array `value` as `submit_decision`. Future mandatory choices require their exact instruction guard; future prompt IDs must not be invented. Legacy answers also accept exact instruction guards. Invalid selector combinations are rejected before an engine action.

Selecting a card can open a cast/plot picker before a spell enters the stack. A guarded picker for that pending cast SHALL be accepted without permitting unrelated stack additions. `play.expectCast:false` describes an intentional no-stack special action such as plot; the executor still uses only current legal engine choices. A known own non-mana activation uses separate `expectAbility:{sourceId,abilityText}`. Its source must be a visible own battlefield object and its announced stack type must be exactly `ACTIVATED_NONMANA`. This permission never admits a trigger, another source/text/controller, or a face-down source forecast.

The projection SHALL retain the already public activated/triggered ability type, source object ID and announced ability text. It SHALL NOT copy the source card's hidden identity, rules, printing or other raw fields. A face-down permanent's public object ID remains public. Stack settlement requires the forecast activation to have been observed and a fresh actionable priority view: an ACK followed by an awaiting-server snapshot with an empty stale stack is not completion.

An XMage ability picker retains decision kind `panel`. For a visible source, it SHALL publish its source object ID and typed legal options, with the selected face name for a spell option. A declared activation at this panel requires a matching own battlefield source and a non-mana activation option. A declared cast requires a visible source from a cast zone and a typed spell option. A cast already pending from priority requires the same source object. The executor credits the resulting stack object only when the card identity, controller, selected face, and spell type match. Generic mode panels and unavailable sources carry no typed picker evidence.

An unseen-information choice SHALL interrupt before selecting a predecision, even if every card ID was previously known. Runtime barriers use existing server `targetZone:LIBRARY` metadata for search/scry/surveil, revealed piles, and the engine's native coin/die keep/reroll prompts. A fresh plan from an already observed information choice may answer it. A committed draw increments only the drawing player's information revision, including a previously seen card; other seats get neither that private counter nor its card identity. Resolution automation, including legacy sequences, fails closed if information evidence is absent.

Preflight conservatively makes a selected instant/sorcery with public scry/surveil/draw/mill/search/reveal/impulse/cascade/discover/random or rival-choice effect text terminal. It also checks the exact declared activated/triggered effect, rather than all unrelated abilities printed on a permanent. A future strategic intention after that effect is rejected with `reevaluation_required` before any cast. Guarded casting modes, targets and payments may follow while the tracked information effect has not begun resolving, including known Ward costs before the main spell. A resolution-entry fence prevents those choice tails from executing afterward even if the card IDs are unchanged or a new prompt lacks its boundary marker. A known native heads/tails call before a public coin effect is distinct from choosing a result after the flip. Library and draw witnesses remain authoritative at runtime. A deliberate `when:priority` response before an existing information spell resolves remains possible; it does not authorize continuing after the information outcome.

Use explicit `reevaluateAfter:true` for uncertain effects not recognized by the conservative preflight. It must be the last strategic intention and stops after settlement, before any phase/turn advance. Later guarded costs are permitted only for a tracked cast/activation; terminal lands, plot or other untracked no-stack choices must literally be last (or mark their last known cost instead). Explicitly terminal stack IDs receive the same resolution-entry fence even when their text is unrecognized. Preflight is not a universal Magic rules interpreter: unmodeled replacement effects, generic random implementations and public rival resolution choices need conservative terminal planning. Do not infer complete coverage from a keyword match or from the absence of a rival action counter. No safety override permits guessing an unseen result.

Sequence failures expose a bounded `error` with code/message, zero-based semantic `actionIndex` and internal `stepIndex`, expected/actual decision kind and mismatched guard field names. Accepted decisions remain counted. `startedAtEpochMs` and `lastSubmission` dispatch/finish/ACK metadata record only server-side execution boundaries, without raw arguments, card payloads, headers or secrets. RPC elapsed time includes transport and processing; it is not a measurement of pure engine time, model thinking or pre-invocation approval delay.

If transport loses a start receipt, `get_sequence_status` can recover the retained seat-owned plan by its exact `startCursor` instead of requiring the lost sequence ID. It returns accepted counts and the recovered ID without submitting another choice. A missing/mismatched cursor is not evidence that an action never executed: reconcile the live state before retrying. Retention is bounded to the process's last forty plans, not durable across restart.

`concede` is the supported surrender tool. It cancels queued work before submitting the game concession (`entireMatch:false`, default) or match quit (`true`). A foreign game is refused before cancellation or RPC. Concession is for a lost position, not a workaround for an invalid plan or a reason to start another game after Felipe has finished.

Source/fixtures reproduce separate issues: the turn schema omitted exact decision/choice IDs; `pendingCast` rejected a pre-stack ability picker; own activated stack objects had no explicit forecast and were omitted by the projection; and an activation's ACK could finish a stale empty-stack plan before its callback arrived. Library choices of already known IDs bypassed the old identity-only information check. These are verified implementation gaps, not proof that each caused a reported live delay.

The player reported Class/plot, two Reckless Rage target roles and Ward discard, exhausted-resource passing, Bird, Opt/scry and a cancellation before approval. No concrete player call/ACK trace was supplied to this worker. No restricted assistant session paths, hidden rival zones or finished/live match state were read. The new workspace AGENTS/trace instructions were read; another worker owns those setup files. Engineering tests below use synthetic inputs, not an invitation or a new match with Felipe. Cancellation before MCP invocation cannot be attributed to Felipe or the engine without outer-call evidence.
