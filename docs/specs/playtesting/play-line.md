# Semantic play lines

## PM-LINE-01 — Submit a complete justified line
A seated agent submits ordered `play_line` actions from its observed game ID and cursor. A line can begin in either player's turn. It supports the existing semantic play, attack, pacing and engine choice inputs. An exact observed choice and its optional value must have the same coverage as the low-level decision tool. A guarded future choice may use a currently knowable selector. The game validates each action at its actual prompt. The executor handles routine handoffs and ends the line at a significant opponent action, new information, a required choice not covered by the line, a configured stop, or an invalid action. Accepted actions stay applied.

After inspecting the current hand, a seat may submit an exact London bottom choice, a guarded Keep and its first land together. Once the engine accepts Keep, the line may cross the seat's own first upkeep and play the land at the next legal main-phase opportunity. An opening line can also start at an observed Keep. A fresh hand, a newly revealed card, an unplanned decision, an opposing start or a public response returns control before the land. From an observed casting prompt, a line may resume exact targets and mana payment for its face-up, unpaid, unresolved spell. It returns control after a reveal. A draw in a trigger's condition describes an event that already happened. Inspect the triggered effect for draws and other new information. An attack may declare its exact own triggers at confirmation. A trigger-order prompt publishes source identity and rule text for a face-up source on a visible battlefield. Its choice can identify that public source and an exact label. A source shared by multiple matching options is ambiguous.

## PM-LINE-02 — Pass with an explicit destination
A terminal `pass_until` action accepts `destination: "my_upkeep" | "my_draw" | "end_step" | "current_turn"` and `policy: "if_no_play" | "decline_optional"` (default `if_no_play`). Upkeep refers to the next own turn and returns control before drawing. Draw refers to the forthcoming own draw, including the same turn when called before the draw step. It returns control at the first actionable state after the draw boundary. The managed MCP engine seat requests explicit priority in its own upkeep and draw steps. A current-turn destination matches every supplied phase, step or priority condition. If the engine skips the requested window or no new card is confirmed in the own hand at the draw boundary, report the actual boundary and any new information without silently claiming the destination. The safe policy stops for a non-mana legal play before the destination. The explicit decline policy supports holding up mana and passing without revealing whether a response exists. Both policies stop for an opponent action, an unknown mandatory choice, or new information. A terminal `pass_priority` makes one deliberate ordinary pass and returns at the next actionable boundary without making another pass.

When `my_draw` follows earlier actions in the same line, its destination is chosen from the state after those actions. An already-skipped opening draw cannot prevent a line that just played a land from passing toward the next actual draw.

An automatic pass stops before the turn-based draw when the public rules of a visible battlefield source indicate that the draw can trigger an ability. This applies on either player's turn and before the executor passes its last upkeep priority. A fresh action at that boundary can deliberately cross it. The guard uses battlefield information published to the acting seat. Public delayed effects outside that projection and conditions that require additional engine state have limited coverage.

## PM-LINE-03 — Return the next decision in the same response
A line returns state and a receipt together. Within a bounded wait, return once the executor completes or interrupts. If the wait expires, return the same plan identity, current progress and seat-visible state, marking that the plan still owns execution. The client may wait for that plan's meaningful stop through the decision-wait tool. A transport cancellation ends the wait while preserving the receipt of any accepted line. Retrying an identical command ID in the same active seat process returns its receipt without replaying actions. Reuse with a different payload rejects. A stale or foreign request cannot affect an active plan.

## PM-LINE-04 — One bootstrap
A single guide request can load all four full guides. Guide loading and tool descriptions teach agents to submit the longest line justified by current information and stop to replan at a new decision. Existing tools remain available to compatible clients.

## Live playtest acceptance

- **PM-LINE-FLOW-1** Casting a modal spell with a confirmed deterministic mode can retain the planned continuation. A mode that reveals previously unavailable cards returns control before a later tactical action.
- **PM-LINE-FLOW-2** A planned decline of a known optional payment can retain the continuation when that branch reveals no new information. Accepting the discard-to-draw branch still requires inspection when the new card becomes visible. The answer must match the legal prompt.
- **PM-LINE-FLOW-3** A pass from an observed stack can advance to the first meaningful boundary. A rival action, a required decision the line cannot cover, or newly visible material information stops the line. An opponent's hidden draw and a draw visible to the acting seat are distinct.
- **PM-LINE-FLOW-4** Own expected triggers can be attached to an observed own resolving source, including a spell whose payment is already pending. Prepared copies and deterministic public triggers can carry a continuation when their source, causality and result are confirmed.
- **PM-LINE-SEM-1** A mana payment can identify a source and color without reproducing its printed rules. It follows the legal engine option and preserves its actual side effects, including painland damage.
- **PM-LINE-SEM-2** A mode, spell ability, alternate cost or cast face can select a unique legal engine option from the same cast. A line announcing a Room's door can pay for that same face and continue through its planned actions. A changed or ambiguous option leaves the next decision unapplied.
- **PM-LINE-SEM-3** Exact targets can be matched to their projected role or visible zone without reproducing a localized prompt. Distinct mandatory target prompts remain distinct. The engine may choose the sole legal opponent for a mandatory target-opponent role when auto-targeting is enabled. A cast can continue past a target role whose exact public selection is already proven by the same spell instance.
- **PM-LINE-SEM-4** Mana-only priority does not interrupt safe passing. A separate legal non-mana play, including an alternate cost, still does.
- **PM-LINE-SEM-5** One typed activation selects an exact non-mana ability of an owned visible battlefield permanent. A line can pay declared mana, select legal targets and continue after the exact activation resolves. The current priority choice supplies the legal ability ID and, when identifiable from a unique public rule, its full source-named `abilityText`. A short summary with an ellipsis or `{this}` cannot substitute for that rule. Ambiguous summaries expose no inferred rule. A mismatched picker, stack object or opponent action interrupts the line.
- **PM-LINE-MCP-1** An agent can distinguish schema rejection, preflight rejection and a running or interrupted line using a stable code and execution evidence. A lost response is recoverable by the same command ID.
- **PM-LINE-MCP-2** Compact state is discoverable via the native MCP schema and retains the IDs, legal choices and current priority needed to continue. Connected catalog exposure requires separate verification.
- **PM-LINE-COMBAT-1** A line can submit and confirm exact legal blocker assignments. Combat can continue after confirmed damage between observed combatants or exact life loss from an observed unblocked attacker. A rival action or unexplained combat change returns control.

- **PM-LINE-FLOW-5** An exact answer to a public trigger-order prompt can opt into following its selected trigger and the final forced trigger. The engine must confirm the public source, ability, instance and placement order. Unknown, changed or additional stack objects, meaningful rival actions, and new information still return control.
- **PM-LINE-FLOW-6** With an applicable public draw trigger on the battlefield, a queued pass returns control during the relevant upkeep before the draw, even under an explicit optional-decline policy. A draw destination with no applicable trigger can still reach the draw. A new command from the returned position can pass deliberately.
- **PM-LINE-SEM-6** An optional casting-cost question can be answered with a guard for the exact visible source and engine question. Queue that choice at the engine's observed point in the announcement, before targets for Burst Lightning. Taking the cost preserves the engine's resulting payment and information boundaries.
- **PM-LINE-SEM-7** A `playAs:"land"` action requires one matching engine choice marked `canPlayLand:true` when it executes. At an empty-stack main-phase priority decision with zero matching land choices, the line interrupts with `land_play_unavailable` before applying the land or later actions. Multiple matching legal choices retain `ambiguous_choice`.
- **PM-LINE-MCP-3** A line supports at most one terminal pass. A `pass_priority` and any cross-turn or end-step destination must be last. An intermediate `pass_until` requires `destination: "current_turn"`, a named engine phase or step, `priority: "self"`, and an immediately following play, activation, choice or combat declaration. A combat action requires the step of its own declaration or `BEGIN_COMBAT`, from which it waits for the next matching declaration in this turn. If the engine skips the declaration or priority has already opened after it, stop before consuming that priority. A phase alone cannot select a combat declaration. The requested policy governs passes on approach and from beginning of combat to the declaration. A missed window or an undeclared decision preserves the remaining actions. An unavailable play at the window cannot execute later. Preflight rejects a premature pass with `bad_sequence`, the action index and the one-pass rule before applying any action.

- **PM-LINE-COMBAT-2** An attack can identify an exact observed player, planeswalker or battle for each creature. The engine must witness the declared assignments before confirming them. Verified damage to a planeswalker or battle can continue through the associated counter change, including lethal loyalty loss and the resulting graveyard move. Other effects and decisions still require independent evidence.

## Acceptance
- PM-LINE-01: exact numeric/array choice parity, a complete deterministic line, an observed library choice, and stops before applying tactics dependent on unseen information.
- PM-LINE-02: safe passing sees free plays, explicit decline can hold up mana, and upkeep and draw have distinct observed boundaries. Unavailable windows, opponent actions and mandatory choices stop safely.
- PM-LINE-03: a decisive line needs one MCP call from an observed cursor. Slow opponent, transport loss and changed command payload do not duplicate actions. A follow-up wait yields the plan stop and current view together.
- PM-LINE-04: one bundle returns all document bodies and the legacy single-guide input still works.

### PM-LINE-REPLAY-1 · Player-authored line explanations

An agent acting from either authorized seat may submit a 1–600 character `reasoning` with `play_line`. The first dispatched decision records the command ID, authenticated player and explanation at the current replay frame. Recovering a receipt preserves the original explanation. A command reused with a different explanation conflicts. A line that never dispatched a decision produces no replay entry. After match completion, a seat replay includes its own notes and an authorized full replay includes both players’ notes. Public and live views omit them. The replay viewer can hide the dashed, brain-marked notes independently of strategic analysis. Older recordings need no migration.


### PM-LINE-WAIT-1 · Command delivery and destination

A zero-duration initial receipt followed by a bounded wait for the same game and command authorizes the same actions and destination as a single long initial wait. A command waiter wakes when its line stops, even before another own prompt. The terminal receipt reports execution ownership, the current seat decision, the witnessed destination or interruption and the frozen executor timing. A rollback takes precedence. Each HTTP wait can expire while the command remains running.

### PM-LINE-WAIT-2 · Opening transition and active execution time

Explicit opponent priority without an own prompt suspends the active budget. A successful acknowledgement of an exact own opening Keep permits waiting for the first turn within the same game and epoch. A fresh own prompt restores active accounting and uses the usual guards. A first opposing turn, new information or a changed epoch interrupts before a queued land. Generic absence of a prompt consumes active time. All sequences retain their maximum wall lifetime. The receipt exposes time under opponent priority, the acknowledged opening transition and other active execution. These observations do not identify a player's thinking time.

`test/line-wait-contract.test.mjs` instruments both client delivery patterns, slow opening, unknown waits and lifetime limits. `product/london-mulligan.local.mjs` compares the two deliveries for the same seeded Pioneer turn via native MCP and isolated Java XMage.
